# 以能量为主的 Evaluation 更新（2026-10-19）

## 1. 主张与指标

作者决定以能效作为跨平台比较重点。先测量再判断优势，保留所有已测延迟。
主指标是完整多头 SDPA 的每次调用能量（µJ/call，越低越好）；相同 H/N/d 下可比较。
辅助报告平均活动功率、延迟及有效 TOPS/W，MAC=2 ops 的约定保持一致。
不同 H/d 的模型分别绘图，不仅按 N 混排优劣。

低功率不自动意味着低能量：E=P_avg×T，能量必须覆盖同一工作量和同一执行窗口。
N1024当前FLOPA/GPU延迟比约70.4/81.7；是否节能仍取决于对应窗口的实测/估计功率。

## 2. GPU 测量

- 仍用固定RTX A6000、原五个N、原始真实轨迹Q/K/V、FP16、完整多头SDPA。
- 沿用已验证的最快Flash/Efficient后端，Q/K/V显存驻留，不含主机传输和投影。
- NVML累计能量计数器已在两张卡只读验证可用；正式固定原GPU UUID。
- 主结果用整卡gross能量，不减去空闲功耗；空闲窗口另存用于检查漂移。
- 每个N：20次预热，CUDA Graph内32次同输入SDPA，10秒空闲基线、10秒负载预热，
  3个不少于10秒的正式持续执行窗口，最后10秒空闲基线。
- 每窗口记录累计能量起止mJ、实际调用数、wall时间、50ms能量/功率轨迹、
  时钟/温度/功率上限；每秒检查是否出现外部compute进程，有则拒收。
- µJ/call=窗口累计能量J/实际SDPA调用数×1e6；三窗口报告中位数与范围。
- Graph使用固定32次SDPA，减少Python提交间隙；这测的是稳态重复执行能量。
  原单调用CUDA-event延迟仍独立保留，不能用它乘稳态功率来伪造能量。
- NVML power.draw在Ampere非GA100上为1秒平均；不能用一个短SDPA前后的瞬时读数。
- GPU与ASIC尚未等精度；当前数值检查作为诊断，最终质量门槛仍须完成。

NVML来源：https://docs.nvidia.com/deploy/archive/R550/nvml-api/group__nvmlDeviceQueries.html

## 3. ASIC 测量与可行性

- 使用对应网表/DDC、同一输入和同一活动窗口的SAIF功耗估计。
- E_IP=P_IP,window×cycles×1.60ns；属于布局前IP估计，不是硅片或整板实测。
- 现有N256/H1/d72点是功耗微基准，不能冒充N1024完整多头SDPA能量。
- 不用N256的常数功率乘所有长N延迟，不把一个head能量直接乘head数填正式数据。
- 全头长N门级仿真代价很大：先完成现有F0/F2和其他功耗点，审查时钟功耗分组、
  网表活动映射及窗口定义，再决定原形长N的完整门级或经验证的活动采样方案。
  采样方案若采用，须另行说明窗口/权重/误差并标明估计；尚无方法/结果时保持空白。
- 当前d72点clock-network占总功耗97.22%，需先核对映射后时钟负载、传播与分组，
  不能据此直接发表低能耗优势，也不能为得到有利结果删掉该分量。

## 4. 边界与图表

- GPU报告整卡传感器能量，包含卡上显存/板级开销；ASIC报告IP估计，排除外部DRAM、
  PHY、封装和主机。两者并列展示时显著标明，直接节能倍数保持空白。
- 若要系统级节能倍数，需加入ASIC外存/PHY能量并给出可审查边界，或取得共同范围。
  缺失部分不能按0处理。
- 主图拟为PixArt/Wan两个子图，横轴N、纵轴每次完整多头SDPA的µJ（可用对数轴）。
  延迟仍在Excel及文字中报告，不筛掉不利性能数据。
- ASIC对应原形能量未齐前不生成虚假的两条完整曲线。
- 主表保留面积、SRAM面积/容量、频率、活动功率、有效吞吐与能效及实现阶段。
- F0/F1和F0/F2同IP范围对照才是P驻留/重叠导致能量改善的直接证据。
